# 분석 노트 — 제어 네트워크의 프로토콜을 이용한 보안 위협 연구

- 서지: 최동준(중앙대 융합보안학과 석사과정), 이재우(중앙대 산업보안학과 교수), 한국전자거래학회지 Vol.25 No.2, pp.99-108, 2020.05
- DOI: 10.7838/jsebs.2020.25.2.099
- 원문: `papers/제어네트워크의프로토콜을이용한보안위협연구.pdf`
- 표기: `[논문]` = 원문에 직접 적힌 내용 / `[추론]` = 내 해석

> ⚠️ **제목과 달리 시리얼 논문이 아니다.** 대상은 이더넷 기반 S7CommPlus(TCP 102번 포트)이다. R1(시리얼)의 근거로 쓸 수 없다. 대신 **"프로토콜에 보안 메커니즘이 있어도 우회 가능하다"** 는 별개 논점의 근거가 된다.

| 방법 | Siemens PLC 1214c AC/DC/Rly + TIA Portal 11을 더미 허브로 연결한 테스트베드 구성 → 연결 과정 및 제어 명령 패킷 분석 → S7CommPlus의 Anti-Replay 메커니즘 우회 → 재전송 공격 |

## 1. 연구 목적
[논문] 산업제어시스템에서 사용하는 PLC 프로토콜의 연결 과정 및 패킷을 분석하고, **프로토콜에 존재하는 보안 메커니즘을 우회하여 PLC를 원격에서 컨트롤할 수 있음을 보이는 것.** 이를 통해 보안 경각심을 제고하고자 함.

## 2. 연구 문제
[논문] 산업제어시스템은 일반 IT 환경과 달리 보안성보다 **안전성·연속성이 중요시**되는 환경이다. 보안 사고 발생 시 물리적 동작을 제어할 수 있어 물리적 피해, 나아가 인명피해까지 초래할 수 있다. 그럼에도 "아직까지 산업제어 시스템에 대한 보안이 많이 강화되지 않은 상태이고 실제로 많은 취약점들이 발생하고 있다."

## 3. 연구 대상
[논문] Siemens PLC의 **S7CommPlus 프로토콜**. TCP 102번 포트 사용.
[논문] S7CommPlus에는 **Anti-Replay 메커니즘이 포함**되어 있으며, 세션 ID라는 2바이트 필드를 사용한다.

## 4. 연구 방법
[논문]
1. 테스트베드: Siemens PLC 1214c AC/DC/Rly + TIA Portal Version 11 + 더미 허브로 내부 네트워크 구성
2. TIA Portal과 PLC 간 연결 설정 패킷, PLC Start/Stop 명령 시 발생 패킷을 캡처·분석
3. TIA Portal로 위장하여 연결
4. Anti-Replay 랜덤 비트 우회 후 재전송 공격 수행

## 5. 핵심 결과
[논문]
- 패킷 분석 결과 `Item value:ID = CPUexecUnit.Operating...` 필드에서 Start/Stop 상태가 구분됨(Stop일 때 0x01)
- 단순 저장 후 재전송은 S7CommPlus의 Anti-Replay 메커니즘에 의해 차단됨
- **우회 방법**: Anti-Replay 랜덤 비트에 대해 응답값에 특정 연산을 더해 특정 필드 영역에 넣으면 우회 가능 — `Anti-Replay = Challenge(0x48) + ...` (구체 수식은 원문 참조)
- 우회 후 재전송 공격으로 **PLC를 실제로 정지**시킴 (Figure 11: "PLC Actually Stopped Due to Replay Attack")
- [논문] "S7Comm Plus 프로토콜의 특성상 102번 포트가 열려 있기에 중요한 동작을 하는 PLC 기기일 경우, 타겟 PLC 기기로 선정하여 PLC를 멈추게 하는 공격도 가능할 것으로 예상한다."

[논문 — 결론의 전제] "이는 **외부망과 연결된 내부 접점 또는 외부에서 제어망으로의 침투가 가능한 공격 시나리오만 있다면** 정상 작동 중인 PLC를 멈추어 버려 큰 피해를 발생시킬 수 있을 것"

## 6. 기존 연구와 차이
[추론] 선행 연구가 S7 프로토콜의 암호화 부재(Lack of Encryption)를 지적하는 데 그친 반면, 이 논문은 **Anti-Replay 메커니즘의 실제 우회 방법을 구현하고 물리적 결과(PLC 정지)까지 도달**한 점이 차이. Stuxnet 기반 변종 악성코드 논의도 언급.

## 7. 한계 (저자 인정 + 관찰)
[논문 — 저자 인정] 명시적 한계 절 없음.

[추론 — 내 관찰]
- 단일 벤더(Siemens), 단일 모델(1214c), 구버전 도구(TIA Portal 11) → 일반화 제약
- **내부망 접근이 이미 확보된 상태를 전제**한다. 저자 스스로 결론에서 "외부망과 연결된 내부 접점 또는 침투가 가능한 공격 시나리오만 있다면"이라고 조건을 붙임
- 제목이 "제어 네트워크의 프로토콜"로 포괄적이나 실제 대상은 이더넷 기반 단일 프로토콜

## 8. 내가 가져갈 것
1. **"보안 메커니즘의 존재 ≠ 보안"**: S7CommPlus에는 Anti-Replay가 *있었는데도* 우회되었다. E26 6.4가 "방화벽으로 구역이 분리되어 있음"이나 "IP 연결이 없음"을 근거로 격리를 인정하는 것과 같은 구조 — **통제 수단의 존재가 그 유효성을 보증하지 않는다**
2. **논문 4.3(IT 경유 접근)의 후속 단계 근거**: 이 논문은 "내부망 접근이 확보되면 그 다음에 무엇이 가능한가"를 보여준다. TRITON이 경로를, 이 논문이 도달 후 결과를 보여주는 구조로 배치 가능
3. **R3·R7의 보조 근거**: 독자(proprietary) 프로토콜의 보안 메커니즘은 리버스 엔지니어링으로 분석·우회 가능 → E26 A-b가 "Known" 취약점만 요구하는 것의 한계
4. ⚠️ **R1(시리얼)에는 쓸 수 없다.** 이더넷 기반이므로 시리얼 논거로 인용하면 오류

## 9. 내 연구와의 관계
**참고.**
- 학술대회 논문(3쪽)에는 인용하지 않아도 됨. 지면이 부족하고, 4.1은 장지웅·김휘강(2013)과 Forescout(2026)로 충분
- **정식 논문에서 유용**: 4.3(IT 경유 접근)의 "경계를 넘은 이후" 단계와, A-b("Known" 한정)의 한계 논증에 배치
- ⚠️ 인용 시 시리얼이 아님을 정확히 인지할 것
