## 1. 연구 목적
[논문] VSAT 및 위성통신 시스템의 취약점을 분석하고, 보안 체크리스트를 강화하여 선박 운영자에게 효과적인 사이버보안 대응 방안을 제시.

## 2. 연구 문제
[논문] 해양·선박 산업의 디지털화로 선박 대상 사이버 공격 위험이 증가. 특히 위성통신으로 연결된 시스템의 취약점이 부각. 한 선박 시스템 IP 주소의 위협보고서에서 **인바운드 위협 수치가 99% Critical**로 나타남.

## 3. 연구 대상
[논문] VSAT(Very Small Aperture Terminal) 및 위성통신 시스템. DFD는 VSAT를 중심으로 **위성 ↔ 선박 내부 시스템 ↔ 인터넷 ↔ 육상 기지국** 간 데이터 흐름을 모델링.

## 4. 연구 방법
[논문] 5단계:
1. DFD 분석
2. STRIDE 위협 모델링
3. Attack Tree 분석
4. Criminal IP 위협 인텔리전스 데이터 활용
5. STRIDE·DREAD 기반 위험 평가

DREAD 5요소: Damage Potential, Reproducibility, Exploitability, Affected Users, Discoverability

## 5. 핵심 결과
[논문]
- **노출 규모**: 2023.12~2024.1 한 달간 **1,627개** VSAT 관련 장치가 인터넷 노출 (출처: Criminal IP, 보안뉴스 보도 인용)
- **STRIDE 결과** (VSAT 대상):
  - Spoofing: 위성 신호 스푸핑, GPS 스푸핑
  - Tampering: 통신 데이터 변조, 펌웨어 변조
  - Repudiation: 로그 삭제/변조
  - Information Disclosure: 민감한 선박 정보 유출
  - DoS: VSAT 시스템 과부하 공격
  - EoP: VSAT 관리자 권한 탈취
- **실제 CVE** (Cobham SAILOR VSAT Ku v.164B019):
  - CVE-2023-44857 — 원격 코드 실행(RCE)
  - CVE-2023-44856, CVE-2023-44855 — XSS
  - CVE-2022-22707, CVE-2019-11072, CVE-2018-19052 — 과거 보고분이나 **여전히 유효**. 웹 인터페이스를 통한 관리자 권한 탈취, **선박 위치정보 및 장비정보 노출** 가능
- **Attack Tree 주요 공격 vector**: 물리적 접근, 네트워크 공격, 소프트웨어 취약점 이용
- **DREAD 우선순위**: 1위 정기 취약점 스캔·침투테스트(42점), 공동 2위(41점) — 강력한 인증 메커니즘, VSAT 웹 인터페이스 접근 제한·모니터링, GPS 스푸핑 탐지·방어, 보안 로그 모니터링·이상징후 탐지, 사이버 사고 대응계획 수립·훈련

## 6. 기존 연구와 차이
[논문] 명시적 비교 없음. 참고문헌은 2건뿐(보안뉴스 기사, 조용현·차영균 2019).
[추론] 조용현·차영균(2019)의 방법론을 **VSAT 단일 시스템으로 좁혀** 적용하고, 여기에 실제 위협 인텔리전스 데이터(Criminal IP)와 DREAD 정량화를 더한 것이 차이. 다만 학부생 프로젝트 결과물(해양수산부 ICT멘토링)로, 방법론적 신규성은 낮음.

## 7. 한계 (저자 인정 + 관찰)
[논문 — 저자 인정] 없음. "향후 연구 방향"을 제목에 넣었으나 결론에서 구체적으로 제시하지 않음.

[추론 — 내 관찰]
- **2쪽 분량**의 발표논문. 핵심 산출물인 표 1(STRIDE 결과), 그림 1(DFD), 그림 2(Attack Tree)가 PDF 텍스트 추출에서 분리되어 **본문만으로는 재현 불가**
- DREAD 점수(42점, 41점)의 **산정 근거와 척도가 제시되지 않음**. 42점이 최대치 대비 어느 수준인지 불명
- "10개 항목 체크리스트"의 전체 목록이 본문에 없음
- 노출 장치 1,627개는 **1차 자료가 아니라 언론 보도(보안뉴스) 재인용**
- 대응 전략이 "인증 강화", "모니터링 구축" 수준의 일반론

## 8. 내가 가져갈 것
1. **인용 가능한 수치**: VSAT 장치 1,627개 인터넷 노출 (단, 보안뉴스 재인용임을 명시하고 가능하면 Criminal IP 원자료 확인 → [확인필요])
2. **인용 가능한 CVE 목록**: Cobham SAILOR VSAT의 CVE-2023-44855/44856/44857, CVE-2022-22707, CVE-2019-11072, CVE-2018-19052. **웹 인터페이스를 통한 관리자 권한 탈취 + 선박 위치·장비 정보 노출**이라는 영향 기술이 내 논지에 직접 쓰임
3. **논거 연결**: VSAT는 E26 1.3.2에서 "class rules 및 statutory regulation이 요구하는 내·외부 통신 시스템"으로 **범위 내(in scope)**. 그런데 이 논문이 보여주듯 실제로 인터넷에 노출되고 RCE 취약점이 존재한다 → 범위 내 시스템조차 이 상태인데, **제외된 시스템은 어떻겠는가**라는 대비 논증에 쓸 수 있음
4. DREAD를 쓸지 판단 재료: 정량화 시도는 좋으나 근거 없는 점수는 오히려 비판 대상. 나는 DREAD를 쓰더라도 **척도와 산정 근거를 명시**해야 함

## 9. 내 연구와의 관계
**참고 (근거 자료 제공용).**
- 방법론은 가져올 것이 없음 (조용현 2019의 축소판)
- **데이터는 가치 있음**: 실제 CVE와 노출 규모는 "위성통신 시스템이 실제로 공격 가능하다"는 사실 근거
- 내 매핑표 **R5**(정보계 시스템의 무결성 훼손 → 육상-해상 정보 혼선)와 연결: VSAT 관리자 권한 탈취 시 선박 위치정보가 노출·변조 가능하다는 것은 곧 육상-해상 정보 불일치의 실현 경로
- ⚠️ 인용 시 "2쪽 학술대회 발표논문"임을 감안. 핵심 논거를 이 논문 하나에 의존하지 말 것
