# 1. TCP 프로토콜
## 1) 개요
- TCP(Transmission Control Protocol) - 인터넷 프로토콜 그룹의 핵심 프로토콜
- 안정적이고 정렬된 통신 채널을 제공
- 신뢰성과 순서화된 통신을 달성하기 위해 TCP는 연결을 유지하기 위해 통신의 양쪽 종단(end)이 필요
- 연결하는 파이프는 기본적으로 보안 매커니즘이 적용되지 않아, 보호되지 X 
	-> 공격자가 연결을 도청하고 가짜 데이터를 연결에 주입하고 연결을 끊고 연결을 하이재킹할 수 있음
## 2) TCP 프로토콜 동작 방식
- 이해를 위한 코드 -> Source code 분석 참조
### (데이터 전송 : 내부)
- 연결이 설정되면 운영체제는 데이터 전송(전송 버퍼)과 데이터 수신(수신 버퍼)을 위해 각 종단에 두 개의 버퍼를 할당
- 응용 프로그램이 데이터를 보낼 때 패킷을 직접 구성하지 않음 => 데이터를 TCP 전송 버퍼에 넣음
- 운영체제 내의 TCP 코드는 데이터를 보낼 시기를 결정
	- 이때, 작은 데이터가 포함된 패킷을 보내 네트워크 대역폭을 낭비하는 것을 방지하기 위해 TCP는 정해진 시간동안 기다리거나, 데이터가 IP 단편화를 일으키지 않고 하나의 패킷에 넣기 충분할 때까지 기다림
- 송신 버퍼의 각 옥텟에는 연관된 순서 번호가 있음 => TCP 헤더에 페이로드의 첫번째 옥텟에 필드
	-> 수신자 측에서 패킷이 도착하면 수신 버퍼내의 올바른 위치에 데이터를 배치
- 성능을 위해 TCP는 데이터가 도착하는 즉시 응용 프로그램의 차단을 해제하지 않고, 충분한 데이터가 있거나 충분한 대기 시간이 경과할 때까지 기다림
- 수신자는 데이터가 수신되었음을 송신자에게 알림 => 확인 응답 패킷을 전송 => 수신이 예상되는 다음 순서번호를 송신
	=> 송신자가 일정 시간내에 확인응답을 받지 못하면 데이터가 손실된것으로 간주하고 데이터를 다시 보냄
# 2. 공격
## (1) SYN 플러딩 공격
- TCP 연결이 설정되는 기간, 즉 TCP 3-way handshake protocol이 대상
### 재전송(Retranmission)
- 최종 ACK 패킷이 오지 않으면 서버는 SYN+ACK 패킷을 여러번 재전송
- 최종 ACK 패킷이 오지 않으면 SYN 큐에 저장된 레코드가 결국 시간 초과되어 폐기됨
```bash
sysctl net.ipv4.tcp_synack_retries

// change the value to 10
sudo sysctl -w net.ipv4.tcp_synack_retries=10
```
