## 1. 전송 계층
- IP 프로토콜(네트워크 계층) : 송신자 시스템에서 목적지 시스템으로 패킷을 보내는 것 까지만
-  패킷의 데이터를 타깃 응용 프로그램에 제공 => 전송 계층의 작업
### 기능의 이해(네트워크 계층에서 빠져있는 기능)
- 어떤 응용 프로그램이 데이터를 받아야하는지 어떻게 알 수 있는가? 수신자가 응답할 때, 송신자 측의 어떤 응용 프로그램이 응답을 받아야 하는지 어떻게 알 수 있는가
	=> UDP는 여기 까지만 처리
- 패킷이 분실, 복제 또는 지연되면 어떻게 해야하는가? 패킷이 배달되었는지 여부를 어떻게 알 수 있는가
- 패킷이 순서 없이 도착하면 어떻게 되는가? 도착 순서가 바뀌거나, 한 패킷이 도착하지 않는 경우, 수신자는 어떻게 해야되는가
- 송신자가 서버에 너무 빠르게 데이터를 보내거나, 수신자가 처리할 수 있는 속도보다 빠르게 데이터를 보내는 경우 송신자에게 속도를 줄이도록 요청하려면 어떻게 해야 하는가
	=> 다른 기능들은 TCP 프로토콜에 의해 처리
	--> IP 프로토콜(네트워크 계층)은 패킷을 전달하는 메커니즘은 구현이 되어있으나, 전달 순서에 대한 보장이 없고, 패킷 손실과 같은 오류를 처리할 메커니즘이 없음

## 2. UDP를 이용한 공격
- 연결기반 프로토콜(TCP)의 경우, 두 컴퓨터가 서로 통신하기 전에 연결을 설정하는 프로토콜을 거침
	-> 발신자와 수신자 간의 상호 작용을 한 번 이상 수행 
	=> 송신자가 스푸핑된 IP 주소를 사용하는 경우, 연결을 설정하기 애뭄 어려움
- UDP 프로토콜 -> 연결기반 X
	- 데이터를 다른 컴퓨터로 보내기 위해 송신자는 단순히 데이터를 UDP 패킷에 넣고 목적지로 보낼 수 있음
		-> 송신자는 스푸핑된 발신지 IP 주소를 사용할 수 있으며, 수신자는 관계없이 데이터를 받음
### (1) Fraggle 공격
- ICMP 기반 smurf 공격의 변형
- (공격 과정)
	- 공격자가 UDP 패킷을 UDP 에코 서비스(포트 7)로 보냄
	- 패킷은 목적지 IP 주소로 브로드캐스트 주소를 사용, 발신지 IP 주소로 피해자 주소를 사용
	- 네트워크에 N개의 호스트가 있는 경우, 피해자는 N개의 응답을 수신
### (2) UDP Ping Pong
- 일부 UDP 서버 프로그램은 패킷에 있는 내용을 검사하지 않고 UDP 패킷을 수신한 후 회신을 보내는 것을 활용한 공격
- (취약한 UDP 서버)
