## 1. 패킷 수신 방법
-  패킷이 네트워크에서 컴퓨터로 들어오는 방식 => 패킷 스니핑이 동작하는 방식 이해 가능
### 1) 네트워크 인터페이스 카드(NIC)
- 기기는 NIC(Network Interface Card)를 통해 네트워크에 연결
	-> NIC는 시스템과 네트워크 간의 물리 또는 논리 링크
-  매체에서 데이터가 전달될 때 네트워크의 모든 NIC는 유선에 있는 프레임을 모두 볼 수 있음
- <커널 내부의 일반적인 패킷 흐름>
	- 프레임이 매체에 도착 -> 헤더의 목적지 주소를 확인하는 NIC 내부 메모리에 복사
	- 주소가 카드의 MAC 주소와 일치하면, DMA(Direct Memory Access)를 통해 프레임이 커널의 버퍼에 추가로 복사됨.
	- 카드는 CPU에 인터럽트를 걸어서 새로운 패킷의 가용성을 알림
	- CPU는 버퍼의 모든 패킷을 큐(Queue)로 복사하여 더 많은 수신 패킷을 위한 버퍼 공간으로 만듬
	- 프로토콜에 따라 이 큐의 데이터를 처리하기 위해 커널이 다른 Callback handler 함수를 호출
		Callback handler 함수 : 패킷을 사용자-공간 프로그램에 할당
- <무차별 모드(Promiscuous Mode)>
	- 의도하는 NIC로 가지 않는 프레임은 처리를 위해 CPU로 전달되지 않고 폐기
		-> 일반적으로는 다른 컴퓨터간 전송되는 프레임을 볼 수 없으므로, 네트워크 트래픽을 스니핑할 수 없음
	=> NIC를 무차별 모드로 전환이 필요(이땐, root와 같은 상승된 권한이 필요)
	- 이 모드가 동작시에는 NIC는 목적지 주소가 카드 자체 주소와 일치하는지 여부에 관계없이 네트워크에서 수신한 모든 프레임을 커널로 전달
		-> Snipper 프로그램이커널에 등록되면 이 모든 프레임은 결국 커널에 의해 스니퍼 프로그램으로 전달됨
- 유선 네트워크에선 무차별 모드 == 무선 네트워크 카드에선 모니터 모드
### 2) BSD 패킷 필터(BFP)
- 정의된 이유
	- 스니핑시 스니퍼는 TCP 패킷이나, DNS 조회 패킷과 같은 특정 유형의 패킷에만 관심
		-> 원하지 않는 패킷을 커널 수준이 아닌 하위 수준에서 필터링을 지원하기 위해 정의
- BFP를 사용하면 사용자-공간 프로그램이 필터를 소켓이 연결할 수 있으며, 기본적으로  커널에 가능한 한 빨리 원치 않는 패킷을 폐기하도록 지시
- BFP는 연산자를 사용해 사람이 읽을 수 있는 형식으로 작성 -> 기계어로 컴파일되어 BPF 드라이버에 전달 -> 저장된 코드는 **setsockopt()** 를 통해 소켓에 연결가능
- 이후, 소켓에 BPF가 설정된 후 커널에서 패킷을 수신하면 BPF가 호출되어 패킷을 수락할지 여부를 결정 => 수락된 패킷은 프로토콜 스택 위로 Push
- 단, Windows와 같은 다른 플랫폼은 패킷 캡처와 필터링 메커니즘이 다름
## 2. 패킷 스니핑
- 패킷 스니핑 : 네트워크를 통해 전달되는 실제 데이터를 캡처하는 프로세스
- 관리자가 네트워크 특성을 이해하고 결함이 있는 네트워크와 구성을 진단하는 데 사용
### 1) 패킷 필터를 설정
- 일부 필터를 설정하려면 SO_ATTACK_FILTER 옵션 이름과 함께 다른 setsockept()호출을 사용해야 함 => 다른 운영체제가 이식이 힘듬
=> 운영체제의 패킷 캡처 기능에 효율적으로 액세스하기 위한 플랫폼-독립적 인터페이스를 제공하기 위해 ==> pcap(packet capture) API 가 등장
- 프로그래머가 사람이 읽을 수 있는 표현식을 사용하여 필터링 규칙을 지정할 수 있도록 하는 컴파일러(표현식을 커널에서 사용할 수 있는 BPF 의사 코드로 변환)
- pcap API는 유닉스에서 libpcap로 구현, 윈도우에서는 WinPcap, 리눅스에서는 pcap은 원시 소켓을 사용하여 구현

### 2) 캡처된 패킷 처리
- pcap API를 활용한 프로그램으로 패킷이 캡쳐되면 
```c
got_packet (u_char *args, const struct pcap_pkthdr *header, const u_char *packet) 
```
호출 =>  세 번째 인수인 포인터가 패킷을 보유하는 버퍼를 가리킴
-> 이 포인터는 unsigned char 유형 => 버퍼의 내용은 내부 구조가 있더라도 일련의 문자로 처리됨
- 이 버퍼는 실제로는 ethernet frame => 시작 부분에 이더넷 헤더가 있음
-> IP 패킷에만 관심있기에, 이더넷 헤더의 유형 필드가 IP인지 아니면 다른 것인지 확인이 필요
- 방법 1 : 버퍼의 시작 부분에서 유형 필드의 옵셋을 찾고 해당 값을 읽는 것(거대하고 복잡한 헤더에 대해는 확장 불가)
- 방법 2 : C 에서 struct와 유형 캐스팅 개념을 사용
	- struct는 인접한  메모리 위치에 저장되는 변수 그룹
	- 버퍼를 struct으로 캐스팅할 때 버퍼를 구조체로 취급하고, 구조체의 필드 이름을 사용하여 데이터에 액세스 할 수 있음
	=> got_packet()에 전달된 버퍼에 이더넷 프레임이 포함되어 이더넷 헤더 구조를 알고 있으면 유형 캐스팅 수행 가능
	=> 이를 이용해 스니퍼에서 캡처된 패킷을 가져올 수 있음(Source code 정리를 참고)
