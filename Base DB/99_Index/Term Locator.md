## 문서 간 정의 차이 (확인된 것)

- **Authentication** — E26 §2는 `a claimed characteristic of an **entity**`, E27 §1.4는 `of an **identity**`. 문언이 다르다. [SOURCE]
- **Defence in depth** — E27 §1.4는 "people, technology, operations 통합 전략"으로, R166 §4.1.16은 "독립적 기술·절차 계층 사용 접근법"으로 정의. 강조점이 다르다. [SOURCE]
- **System Categories** — 정의 원문은 E22 §3.1 Table 3. E26·E27·R166은 이를 참조한다. 인용 시 **E22를 출처로 쓴다.**
- Cyber incident 정의에서 E27은 `Cyber incidents do not include system failures`를 명시한다. E26·R166에도 동일 문장이 있는지 [확인 필요]
- **Cyber incident** — MSC-FAL §2.1은 `an occurrence **or a sequence of occurrences**`로 정의해 연쇄 사건을 포함한다. E27 §1.4는 `An event resulting from any offensive cyber manoeuvre`로 공격 기인을 전제한다. 범위가 다르다. [SOURCE]
- **CBS** — MSC-FAL §2.1, E27 §1.4, E22 §1.5.2 Table 2의 정의문이 거의 동일하다. 사실상 IMO 정의를 IACS가 채택한 형태다. [INFERENCE]
- **IT / OT** — MSC-FAL §2.1은 IT/OT를 모두 `CBSs that are focused on...`로 CBS의 하위 개념으로 정의한다. E26·E27은 `Devices, software and associated networking...`으로 장치 집합으로 정의한다. **상위 개념이 다르다.** [SOURCE]
- **Cyber risk management** — MSC-FAL §2.1(=§3.1)에만 정의가 있다. `tolerating, terminating, transferring or treating`의 4T 구조. R166 §4.1.11에도 항목이 있어 문언 대조 필요. [확인 필요]

## Database에 원본이 없는 용어 출처

다음 용어는 자료에서 언급되지만 정의 원문이 `Database/`에 **없다**:

**해결됨 (2026-08-18)**

- IEC 62443 보안 프로그램 용어 (SPE, ML 성숙도 레벨, SL 보안 레벨) → **62443-2-1 §3.1, §4.2, §4.3에서 1차 확인 가능**
- NIST CSF 기능 정의 → **CSF 2.0 §2에서 1차 확인 가능**

**여전히 1차 근거 없음**

- IEC 62443 시스템·제품 요건 용어 (SL-T / SL-A / SL-C, FR/SR 등) → **-3-3, -4-2 미보유**. 강의 노트(2차)에만 존재
- NMEA 0183 / NMEA 2000 용어 → 원문 없음. 파생 docx에만 존재
- IEC 61162 문장·필드·체크섬 용어 → 보유본이 **미리보기 14쪽**이라 §7 본문 없음
- IEC 61162-450 (LWE) 용어 → 원문 없음
- IEC 62541 (OPC UA) 용어 → 원문 없음
- Purdue Model → 강의 노트 및 파생 docx (2차)
- ~~NIST SP 800-82 OT 용어~~ → ✔ **해결**. 최종본 §2(OT 개요)·§5(아키텍처)에서 1차 확인 가능. 단 CSF 매핑은 **1.1 기준**
